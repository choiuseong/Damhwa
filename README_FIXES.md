# 담화 시연 전 수정본

첨부된 2026-10-02 소스를 기준으로, 앞서 확인한 대화 시작·종료, 일정 연동, 채팅 연동, 오류 안내 및 일정 후보 검토 문제를 수정했습니다. 기본 화면 디자인과 마스코트는 유지했습니다.

## 1. 적용 방법

기존 작업과 섞기 전에 이 폴더를 별도 위치에 풀어서 확인하세요. 프론트만 바꾸면 동작하지 않습니다. **백엔드와 DB 마이그레이션도 함께 적용해야 합니다.** 팀의 최신 코드가 첨부본보다 변경되었다면 `CHANGES.patch`와 변경 파일 목록을 참고해 병합하세요.

### 백엔드

Node.js 22.13 이상과 PostgreSQL이 필요합니다. 기존 환경이 있으면 그대로 사용합니다. 개발용 DB가 없다면 프로젝트의 `docker` 폴더에서 `docker compose up -d`로 준비할 수 있습니다.

```bash
cd backend
npm ci
```

`backend/.env.example`을 `backend/.env`로 복사하고 DATABASE_URL, OPENAI_API_KEY, PORT를 실제 환경에 맞게 입력합니다. API 키는 백엔드에만 넣습니다.

```bash
npm run db:generate
npm run db:migrate
npm start
```

`db:migrate`는 기존 초기 마이그레이션과 새 `20261020020000_demo_fixes` 마이그레이션을 적용합니다. 기존 사용자·일정·대화는 삭제하지 않습니다. 새 사용자 토큰 및 중복 방지 필드와 채팅 테이블을 추가합니다.

### 프론트엔드

```bash
cd frontend
npm ci
```

`frontend/.env.example`을 `.env`로 복사하고 아래 값을 설정합니다.

```dotenv
EXPO_PUBLIC_API_URL=http://백엔드_PC의_로컬_IP:3000
```

휴대폰에서 테스트할 때 localhost 대신 휴대폰에서 접근 가능한 PC 주소를 사용하세요. 서버와 휴대폰이 같은 네트워크에 있어야 하며, 환경변수 변경 후 Expo를 다시 시작하세요.

```bash
npm start
```

실제 음성대화는 프로젝트의 기존 WebRTC 네이티브 모듈을 포함한 개발 빌드에서 실행합니다. 기존 개발 빌드가 있다면 사용하고, 없다면 frontend/README.md의 빌드 명령을 참고하세요. 백엔드 주소를 비워두면 서버 없는 데모 모드로 동작하며, 글 입력과 정해진 자동 답장으로 흐름을 확인합니다.

## 2. 변경 내용

- 대화 화면 진입 때 고정된 userId=1로 서버 대화를 생성하던 처리를 제거했습니다. 데모 인사는 서버 없이 시작하며, 실서버의 사용자 등록·대화 저장은 필요할 때 수행합니다.
- 실서버 사용자 ID와 세션 토큰을 앱 설치별로 발급·보관합니다. 사용자 간 대화·일정 접근을 제한합니다. 로그인 화면을 추가한 것은 아닙니다.
- 대화 종료 중 저장 오류가 나도 결과 화면이 열립니다. 결과 화면의 확인 버튼에서 대화와 일정을 다시 저장할 수 있습니다. 메시지와 일정은 같은 요청 재시도 시 중복 저장되지 않습니다.
- 프론트 일정 저장·조회·삭제를 `/users/:userId/schedules` 계열로 통일했습니다. 서버가 반환한 ID와 날짜·분류·장소를 사용합니다. 일정 삭제는 서버 성공 후 화면에 반영합니다.
- 실제로 없던 `/conversations/end` 호출을 제거했습니다. 대화 결과는 사용자 발언 일부와 규칙 기반 일정 후보입니다. 화면에 이를 표시하며, AI 요약 기능을 새로 구현한 것은 아닙니다.
- 일정 결과 화면에서 제목·날짜·시간 수정과 후보 제외를 지원합니다. 불명확한 날짜·시간은 확인을 요구합니다. 미래 날짜를 `YYYY-MM-DD HH:mm` 형식으로 입력합니다.
- 오전 12시 해석, 잘못된 시·분, 존재하지 않는 날짜를 검증합니다. 명백한 부정·취소·과거 표현은 일정 후보에서 제외합니다. 복잡한 자연어 의미 분석은 별도 과제입니다.
- 새 대화 시 이전 transcript, 결과, 경과 시간을 초기화합니다. 이전 세션의 늦게 도착한 이벤트는 무시하며, 연결 실패 및 화면 이탈 시 오디오 리소스를 정리합니다.
- 채팅방과 메시지를 DB에 저장하고 3초 폴링으로 다른 기기의 메시지를 조회합니다. 전송 실패 시 문장을 유지하며, 같은 문장의 재시도 중복을 방지합니다. 메시지 전송 응답으로 조회 커서를 앞당겨 중간 메시지를 건너뛰던 문제도 방지합니다.
- 신고·차단은 상대 메시지를 길게 눌러 대상을 선택합니다. 신고는 DB에 저장하며, 차단한 사용자의 메시지는 서버 조회에서 제외합니다. 운영자용 신고 관리 화면은 포함하지 않습니다.
- 공용 기본 방은 모든 사용자에게 보입니다. 위치가 포함된 새 방은 목록 조회 시 반경 2km로 필터링합니다. 위치는 방 탐색용이며 GPS 인증이나 접근 통제를 구현한 것은 아닙니다.
- `/devices`에서 푸시 토큰을 저장합니다. 일정 알림은 기존 기기 로컬 알림을 사용하며, 서버 푸시 발송 작업자를 추가하지는 않았습니다.
- 채팅과 일정의 연결 오류를 숨기거나 성공으로 표시하던 부분을 안내 메시지로 바꿨습니다. 채팅 참여자 숫자 고정 표시를 제거했습니다.
- 앱 상태 복구 구독 및 변경 파일의 린트 오류를 정리했습니다.

## 3. 검증

```bash
cd backend
npm run db:generate
npm run typecheck
npm test
```

```bash
cd frontend
npm run typecheck
npm run lint
```

자세한 결과는 TEST_RESULTS.md를 확인하세요. 테스트는 메모리 PGlite의 독립 DB와 로컬 HTTP 서버에서 수행하며 운영 DB를 변경하지 않습니다. 일반 PostgreSQL에서의 Prisma 마이그레이션 배포 및 휴대폰 실기기 동작은 팀 환경에서 확인해야 합니다.

## 4. 시연 점검 순서

1. 데모 모드에서 서버 없이 대화 화면을 열어 인사와 글 입력을 확인합니다.
2. 실서버 개발 빌드에서 마이크 권한을 허용하고 음성 입력·답변 음성을 확인합니다.
3. '내일 오후 3시 치과 예약'을 말하고 종료한 뒤 날짜·제목을 확인합니다.
4. 일정 후보 수정·제외를 확인한 후 저장하고 달력에서 확인합니다.
5. 서버 연결을 끊었을 때 저장 실패 안내가 나오고, 복구 후 재시도가 되는지 확인합니다.
6. 휴대폰 2대에서 같은 채팅방에 들어가 서로 메시지를 보냅니다.
7. 상대 메시지를 길게 눌러 신고·차단하고 차단된 메시지가 사라지는지 확인합니다.
8. 마이크·위치·알림 권한 거절, 앱 이탈·재진입, 다시 대화하기를 확인합니다.

## 5. 범위와 남은 확인

실기기 마이크·스피커, 통화 끊김, 실제 알림 발송은 이 환경에서 테스트하지 못했습니다. AI 자동 요약, 이웃 간 음성통화, 관리자 신고 처리 화면, 계정 로그인·복구, 서버 푸시 작업자는 이번 수정에 포함하지 않았습니다. 토큰은 기존 AsyncStorage에 보관하는 시연용 익명 세션입니다. 데이터 초기화 메뉴는 기존대로 기기 로컬 기록 초기화이며 서버 삭제 기능이 아닙니다.

원본과 다른 파일만 확인하려면 CHANGED_FILES.md 및 CHANGES.patch를 보세요.
